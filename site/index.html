Build applications,
not PoCs.

Swarm Builder is a canvas for agent workflows that compiles to a Python project on pydantic-graph or LangGraph. Every compile is validated before you see it: the project syncs, imports without a key, and runs end to end. What you export is code you own, with pinned dependencies and no runtime to host.

View on GitHub Run it locally in two commands

Local-first. Python 3.11+ and uv. Bring your own model route: OpenAI, Anthropic, DeepSeek, Bedrock, or any OpenAI-compatible endpoint.

Most visual builders make you a tenant of their runtime.

You draw a flow, and the result is a JSON document only that product can execute. Moving it into a real application means re-implementing it, or shipping the builder alongside your code. Swarm Builder inverts this: the canvas is an editor for a Python project. The graph document is validated against a schema the server owns, the project is emitted from templates, a coding model fills only the marked body regions, and a boundary check proves it touched nothing else. The canvas is where you think; the repository is what you ship.

From a sentence to a running project

Describe the workflow. The model drafts nodes and edges by title; deterministic code derives ids, decision branches, fan-out wiring, state fields and layout, then Phase 1 review checks it and feeds any error back for repair. You land on a canvas you can edit, run, and compile.

Run executes the compiled project with your credentials and traces it node by node on the canvas. Edit a node and run again: a stale project is recompiled first, in the same stream.

Compile is five phases for PydanticAI, nine when you also want the LangGraph export. Nothing is written to disk until review passes; a failed compile leaves the project in place for inspection.

The export is a project, not a file

Built on open frameworks you already know
The generated code is plain pydantic-graph and PydanticAI, or LangGraph with LangChain used only for the model call. No Swarm Builder import anywhere in the output. Read it, review it, put it under your CI.
Integrates into any Python application
from swarm_workflow.graph import graph, then await graph.run(...). It is a package with a pyproject.toml, so it installs like anything else you depend on.
No dependency on the builder at run time
Swarm Builder is a developer tool. Delete it after compiling and the project still syncs, imports, and runs. The validation gate proves this with every credential variable stripped.
Validated before you ever look at it
A compile that reaches you has passed uv sync, a keyless import, a rendered-diagram golden, a node-set assertion, and a dry run with a test model. A model mistake cannot corrupt graph structure, because the model never writes graph structure.

Text to workflow, then edit like an engineer

Take a support ticket as plain text. Classify it as "billing" or "technical" with a rule-based step that returns exactly one of those words and stores the original ticket text in state. Route on the classification: billing tickets go to an agent that explains refund policy; technical tickets go to an agent that suggests a fix. Both agents read the original ticket from state. Finish with an agent that writes a two-sentence customer reply.

Compared with n8n and Langflow

Both are excellent at what they are for. The difference is what you hold at the end.

Swarm Builder n8n Langflow
What you export A Python project: pyproject.toml, source, tests, pinned deps Workflow JSON for import into an n8n instance1 Flow JSON describing components and edges2
Where it runs Anywhere Python runs; no Swarm Builder at run time An n8n server (self-hosted or cloud) The Langflow server, or its LFX executor with the flow JSON3
Orchestration framework pydantic-graph / PydanticAI, or LangGraph. Open source, pinned n8n's own engine Langflow components (LangChain-based)
Code you can read and change All of it; the model writes only marked regions, verified by hash Code nodes inside the JSON Custom components in Python inside the flow
Validation before export Schema review, sync, keyless import, golden diagram, dry run Run the workflow Run the flow
Text to workflow Built in; reviewed by the same checks as a compile AI workflow builder (cloud) —
Best when The workflow is part of a Python application you maintain Integrating many SaaS APIs with a hosted automation platform Prototyping LangChain flows visually
  1. n8n, Export and import workflows: workflows are saved and exchanged as JSON and imported into an n8n instance.
  2. Langflow, Import and export flows: an exported flow is a JSON file of nodes, edges and metadata.
  3. Langflow, About LFX: a lightweight executor that runs flow JSON without the full server. Observed September 2026; both projects evolve quickly. Swarm Builder is not affiliated with either.

Quickstart

The frontend bundle is committed, so the whole install is uv sync. Point UV_CACHE_DIR at a writable directory; the compile gate shells out to uv and inherits it.

Model routes come from a DeepSeek Harness settings.yaml if you have one, or from SWARM_MODEL. A .env at the repo root is loaded at startup. To try the pipeline with no credentials at all, set SWARM_FAKE_FILL=1. 

git clone https://github.com/zaterka/swarm-builder
cd swarm-builder
export UV_CACHE_DIR="$(pwd)/.uv-cache"
uv sync
uv run swarm-builder
# Swarm Builder listening at http://127.0.0.1:8420
